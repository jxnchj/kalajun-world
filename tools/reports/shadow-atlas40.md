# Round 40 near-shadow atlas candidate (default OFF)

Micro's standalone five maps are NOT safe for the current 16-sampler hardware over the full route. The real worst known lodge wood material uses 5 independent surface samplers (legacy/end/color/normal/roughness), array-cloud 1, PBR 2, room/contact 2 and spot shadows 3 = 13 before CSM. Thus standalone micro needs 18, close needs 17. Legacy two-map cloud costs another slot. Runtime and tests now reflect this. Earlier 16-slot micro grass/cabin captures precede the corrected guard and prove only that local image, not full-route support.

`nearShadowAtlas40=1&nearShadowDetail=micro` is an unadopted candidate. `nearShadowAtlas40Capability` checks explicit request, micro mode, actual array-cloud use, PCF, max texture size >=12288 and >=16 fragment samplers. Five original maps remain [4096,4096,4096,2048,2048]. First three share one 12288x4096 UInt depth target; the two far maps remain separate. Material samplers become atlas/far-A/far-B (three); the old five-element directional sampler array is removed, not merely pointed at duplicate textures. Full known material budget is then 16.

Owner creates no hooks/targets unless explicitly enabled. Install after CSM depth/map configuration and before initial shadow rendering. Every near light retains its own camera, frustum, update flag and schedule. Per-light updateMatrices sets target scissor before native clear; getViewport supplies its unchanged 4096 tile. The owner initializes reversed-depth camera projection explicitly because preassigned targets skip native allocation. Destroy owner before CSM destruction. Assert compatibility before main rendering; changing PCF, map ownership or size requires returning to the default scene, not silently rendering unsupported five independent samplers.

Native source evidence: WebGLShadowMap checks each light's needsUpdate independently; computes map size using frameExtents; calls updateMatrices; binds/clears target; then selects viewport. WebGLRenderer.setRenderTarget installs target scissor. WebGLLights still sees five shadow metadata entries, while the custom shader provides three explicit sampling uniforms. WebGLTextures' depth attachments use framebufferTexture2D; current array-target layer binding only covers color attachments, so this is not a native depth-array implementation. Native SunLightShadow is fixed to two cascades with a different fade/update model and is not substituted.

Every original five Vogel PCF taps retains its local coordinate, radius, depth bias, receiver IGN and weight. Each individual tap clamps to the original local half-texel edge before mapping into the atlas, preventing adjacent-tile bleed. Receiver footprint derivatives stay in original local coordinates before branches. The solar-depth experiment and ShadowMaterial are rejected. No maps are resized and no light/shadow feature, density or cadence is dropped.

18/18 targeted tests pass (near-shadow detail plus atlas). Atlas tests exercise the actual installed Three WebGLShadowMap for due-layer clears, skipped-layer preservation, viewport selection, native five-loop shader expansion for standard/physical/lambert/phong with overlap/footprint/zero-fade, explicit capability gates and once-only target disposal. CPU arithmetic tests are not GPU pixel acceptance: 1/3 UV packing can have rounding differences, and real sampler count, framebuffer completeness, cold/room/night transitions, pixels, cadence and performance remain browser gates. Default stays OFF until these pass.


## Caster pixel phase and preparation

Atlas tile X offsets also affect caster `gl_FragCoord` dithering (ecology LOD, spruce branches and far impostors). The owner now scopes a renderBufferDirect wrapper only inside native shadowMap.render. Actual depth/distance materials receive a final compile hook that expands their shader chunks and substitutes local fragment coordinates (xy minus tile origin, unchanged zw). Camera identity sets origin 0/4096/8192 for near tiles and zero for far/spot maps; finally restores the renderer function and resets origin to zero, including failures. Existing object onBeforeShadow remains untouched. Disposed lazy materials remove the hook/owner reference.

`owner.installDepthMaterial(material)` is public for compileShadowWorld to apply before shader warming. Without this eager preparation, first actual shadow use adds a shader variant and can cause a new synchronous first-frame compile tail; runtime wrapping is only the coverage fallback for newly created lazy depth variants, not evidence of acceptable load time. Candidate shader/material parity and load tail remain browser gates.

## Owner reconstruction cache repair

First real A → standalone five maps → B comparison exposed a white frame/GL1282 on owner reconstruction. Three caches programs per material and runs onBeforeCompile only on cache miss; a fixed atlas key can retain the retired owner's null uniforms. Each owner now exposes a unique `shaderKey`, also used by depth variants. Environment colour keys must include that key, and an explicit live owner replacement must mark registered materials needsUpdate (changing a key callback alone does not trigger Three's program refresh). A test executes the installed WebGLRenderer.getProgram cache branch and verifies both colour and depth bind new owner uniforms after A → baseline → B. 9 atlas tests pass. Actual reconstructed-frame/GL validation remains required; this addresses the confirmed cache defect without asserting it was the only cause.

## Contact four-cascade candidate: source verification (2026-10-26)

The four-cascade candidate is implemented as explicit `nearShadowDetail=contact&nearShadowAtlas40=1`: splits `[4,60,180,500]`, maps `[4096,4096,2048,2048]`. The first two share one 8192×4096 atlas; the last two retain independent 2048 maps. This keeps three directional shadow samplers and the known full mixed-wood route within 16 total fragment samplers. Standalone contact requires 17 with array clouds (18 with legacy clouds), while the explicit atlas requires PCF, actual array clouds, at least 8192 maximum texture size and 16 samplers. Auto/default does not select contact or allocate the atlas.

The adopted default 60/180/500m far boundaries remain exactly equal in real CSM frustum tests for both depth conventions; original map sizes, radius, normal bias and depth bias remain equal. World texel pitch is no worse. The 4m map is additional, not a reduction in vegetation, geometry, existing map density or coverage. It nevertheless adds rendering/memory work: compared with the default, one extra 4096² map corresponds to 64 MiB depth plus 64 MiB colour attachment storage nominally; this is not measured driver VRAM.

`node --test web/src/v2/near-shadow-detail.test.js web/src/v2/shadow-atlas40.test.js` passes 24/24. Existing tests include real native four-cascade shadow rendering with one skipped near tile and one due far map, correct local caster coordinates, independent far uniforms, and standard/physical/lambert/phong four-loop shader expansion with footprint on/off. Five-cascade lifecycle/cache tests remain passing. No source defect was found in these two modules during this verification.

This verifies source contracts only. Environment contact shared-ORM/overlap wiring, actual browser frame/GL checks, same-view motion quality, room/night material coverage, and interleaved GPU timing remain required. Contact stays default OFF; no performance improvement or visual acceptance is claimed here.
