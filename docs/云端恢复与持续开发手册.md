# 恢复顺序与完成条件

1. 核对最新用户指示、远端main、当前环境身份及磁盘余量。目录已存在时先检查，不覆盖、不清空。

2. 在可写目录重新取得明确提交的仓库及Git LFS对象，核验对象完整性。远端出现他人新提交时先比较，不强推、不倒退main。

3. 将阶段备份下载到隔离检查目录，核对SHA-256、文件清单和安全路径；保留原包不变。不得直接整包覆盖仓库。

4. 建立差异清单：GitHub已包含、备份新增、只存在候选、仅有历史记录、未执行、明确失败、需重做。每项列来源、哈希、依赖和下一步。

5. 逐项恢复经过核验的文件；候选仍保持未采用状态。旧测试证据只用于追溯，不能代替恢复后测试。

6. 核验运行环境、构建和相关测试，做一次从独立保存内容重建的恢复演练。只有恢复点能够实际使用，才继续大量新开发。

7. 按原行动计划继续；所有未完成、失败、未验收项保留在看板，不能因换环境跳过。

# 成果保存与同步

- 本地工作目录不是唯一成果存放处。只在本机commit或生成ZIP都不算独立保存。

- 每个有价值的小阶段在文件稳定后保存独立增量检查点；连续工作约30分钟未保存时，主动检查并在安全边界保存。长任务应尽可能分段保存可续算输出，不打包正在写入的一半文件。这是目标节奏，不是断线情况下的硬性保证。

- 每个检查点包括基线提交、文件哈希和清单、必要新增资产、恢复说明、通过／失败／未运行／待验收状态、未完成项及下一步。

- 已在GitHub/LFS且确认可取回的大资产不必重复打包；保持清楚的“基线＋增量”对应关系，避免过长增量链。必要时合成新的完整增量恢复点。

- 上传后确认远端版本、大小与校验信息；关键恢复点下载验证。新检查点核验完成前保留上一个已验证版本。

- GitHub维持约4小时、稳定节点同步，重要阶段提前。未验收候选只能明确标记为中间态，原开关不变。保存与验收分开，保存成功不等于功能通过。

- 排除凭据、浏览器配置、缓存、临时环境及无关文件；遵守Git LFS。推送后独立核对远端提交哈希，不强推、不部署、不改仓库可见性。

- 任一独立保存途径失败时保留另一份；两者都失败时停止扩大未保存工作量，先解决保存问题。

# 已验证的环境与工具

以下为此前跑通的配置，恢复时先验证可用性，不盲目照抄旧绝对路径，也不重新走已失败路线。

- 云端Linux；此前Node 24.22.1、npm 11.9.0，依赖按仓库锁文件安装。工具版本变化要记录并复测。

- 原生Chrome使用ANGLE SwiftShader：`--use-gl=angle --use-angle=swiftshader`。不使用`--no-sandbox`，不关闭GPU watchdog，不以降低场景密度、细节或画质换取通过。

- 原生验收目标：1280×800，DPR1，RGBA16F颜色、Float32深度、4倍MSAA；先做实际能力和读回验证。使用仓库`tools/cloud-review75`里的启动、监视和验收说明。

- 常规监视上限2GiB；此前完整软件渲染场景使用明确选择的software-world档位，上限4GiB，启动前和实际启动前可用内存均至少8,000,000,000字节，运行时至少4,500,000,000字节；不自动扩大。外层1320秒、清理预留10秒，watchdog180秒、fence210秒。仅清理可验证属于本次任务的进程。

- 诊断JSON下载曾不可靠；已跑通的方法是页面“显示诊断JSON”，原生复制到文本编辑器另存，再验证文件。截图须核对真实场景与诊断状态，错误层后的像素不算通过。

- Blender使用官方隔离便携版5.2.3 LTS；旧系统4.3.2无法正确读取项目源文件。官方归档SHA-256：78486c018b4443efe5e75ab54c290ed8c15abafd249b862c2c9ce2530a918eec。仅在需要且本地缺失时重新获取并核验，不替换系统版本。

- 不默认转用用户Mac，不动用本地Codex作为云端验收替代。不得为了测试改变用户系统或网络安全设置。

# 每次接续必须先读的内容

恢复后将本手册与机器可读检查点清单纳入项目文档，并同步到独立备份。每次接续先读：用户最新约束、当前差异清单、最新已验证恢复点、环境与工具说明、行动看板及失败记录。

记住方案和工具设置，不等于文件已保存；记录“任务运行中”也不等于重启后进程仍在。每次必须重新核实实际文件、哈希和进程，状态变化要同步更新。任何新版本都应能明确回答：从哪个基线恢复、补回了什么、缺了什么、测试了什么、下一步是什么。
