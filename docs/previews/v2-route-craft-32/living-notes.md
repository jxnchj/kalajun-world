## 实际内容

原113间木屋的完整外壳、室内、门廊、雨棚、长凳、柴架与提桶全部保留。每户用稳定实体ID选择一种额外生活使用组，不随相机或重新载入改变：

- 饮茶40户：窄茶桌、完整原精制茶壶与两只茶碗、门廊栏杆披巾、低木箱。
- 手作28户：另一位置的工作桌、两只木纺锤与浅碗、独立小巾架、折叠织物及收纳箱。
- 晾晒45户：低木晾架、两幅独立弯曲织物、收纳箱与折叠布品。

这是原创牧居使用情境，并非测绘复刻，也不是用随机改颜色冒充逐户差异。三种组合均位于原门廊范围，中央门道 x=0.45–1.55m 保留；没有扩大植被排除范围，没有移动原建筑。

## 资产与运行成本

可编辑源：`assets/src/v2/pastoral/household-living-32.blend`；正式GLB：`web/public/assets/v2/household_living.glb`。源工程保留既有PBR贴图，导出GLB只保存几何/UV/法线/AO和源材质名，运行时强制复用已加载木屋的实际材质和纹理。缺失材质明确报错，不降级为无贴图材料。

15源材质组共35,272三角（11,780 / 11,064 / 12,428）；GLB 2,217,276字节，gzip 548,901字节。113户新增1,340,252实例三角，按原256m分区及使用组实例化为460批，每个使用组5批。几何/贴图不按距离删减，原350m建筑投影范围沿用；实际屏幕绘制量和帧耗由浏览器验收判断。新增运行材质对象0、纹理0、灯光0。

原木屋和毡房GLB、原基础室内GI字段保留；另外以完整原木屋+三种对应户外组，重烘三套天空/太阳一次与二次反射、接触、开口遮挡和闭门端点。各组自身局部AO/天空可见度也已分别烘焙，参与实时太阳和室内灯光阴影。逐户原有新增遮挡依赖已闭合；仍是原有两次静态反射近似及门开度端点插值，不是完整动态GI。

## 逐户室内间接光依赖补齐

`tools/blender/v2_household_room_bake.py` 读取原木屋与对应生活组，135.93秒完成3套场景的开/闭门天空及太阳一二次、接触和开口字段。房间外部几何曾使原启发式把239个室内有效探针误判为238，已保持原室内有效网格，在同样96个方向上完整重算；原通用烘焙默认行为保持不变。所有字段仍9×5×7、239个有效探针。

`household-room-fields.js` 按住户进入时懒加载并核对原木屋和户外GLB源哈希；不会在林溪/户外启动读取三套额外传输表。完全相同的字段载荷精确引用原字段，不做舍入或简化。三包目前为598,328 / 598,334 / 611,755字节原始JS；3种生活布局同时访问后有相应额外CPU数据与已访问房间缓存，未宣称零成本。

受既有门廊遮挡和新器物位置约束，改变量很小：饮茶/手作的一阶天空及所有一阶太阳与原字段逐字节相同；晾晒一阶天空10个half值改变，最大约0.0000186。3组二次天空47–93个值、二次太阳11–12个值改变，全部保持。闭门端点同样完整重烘，不能把这项依赖修复宣传成明显改变全室亮度或已完成完整GI。

新的7项检查验证全部来源/字段、四次3D采样不变、三户选场、接触图、加载中换户、dispose和门开闭准备顺序；原室内相关54项回归通过。`prepare()`先等待当前变体注册，随后等待其闭门端点，不会提前把bundle装载完成当作完整ready。

实际浏览器室内检查应确认 `roomSkyBounce.household.key = house_a-living-0/1/2`、`bundleReady/closedReady/ready = true`、`pending = false`，且 `roomContact.field` 同key。主代理继续实际场景验收。
