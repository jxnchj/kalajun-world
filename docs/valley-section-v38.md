# 第38轮：河谷共享非对称横断面候选

状态：组合已通过同机位实景与沿岸行走验收，源码默认启用；仍是艺术中间态，最终默认入口随集成构建复核。侵蚀侧灰浅带明显缩窄，整体水岸美术未结案。

现在普通 `view=river-valley` 默认采用 `valleyLandform + valleyMeanders + valleySection`。`valleySection=0` 对照旧弯道断面；`valleyMeanders=0` 对照直线低滩；`valleyLandform=0` 关闭整组恢复旧路径。此次断面调整不再移动中心线、不添加石块遮挡植物、不改全局光色。适用范围明确限定已验河流 `river-32d9cab5-5bea75bb` 的代表段。

## 实际依据与修改

父任务在 `(-117,2996,10,-20,-20)`、1280×800、time870、地形准备完毕时关闭近水、远水、泡沫三个材质；`docs/previews/v2-route-craft-38/valley-gray-water-hidden.png` 仍完整保留灰带。它主要来自河床/岸坡几何和材料，不能继续当作反射处理。

旧河床函数在两侧都强制水边深度和坡度归零，在宽河谷形成连续平坦浅水平台。本次让侵蚀侧以非零入水斜率进入槽底，仅实际内弯形成浅滩。内弯符号由镜像圆弯证明：正曲率朝 `(-flowZ,+flowX)` 正侧转弯，所以正侧才是内岸。旧候选对这一符号的使用相反且叠加了连续随机沉积场；新候选不沿用该场来决定两侧浅滩。

CPU 河床与水体 shader 在 `river-bed-profile.js` 共用系数与公式。新增小型顶点参数传入同一断面权重及左右沉积量；水顶点、实例密度和细节级别均保留。默认权重零立即返回原公式。

根部映射扩大到“中心线不动、断面改变”的接点段，避免丢失原草花。新候选的物理湿草资产生成按真实水域覆盖和地形支撑判断，不再用邻水面的无限水平延伸加 3.5cm 固定余量排除合法湿岸；旧候选维持原判断作为对照。运行时地形接地和石头扫掠检查仍在。

## 针对验证

- 镜像圆弯验证内外岸符号；CPU/实际发出的 GLSL 标量表达式全组合采样相同。
- 真实河谷 48 段岸坡单调、无反向沟槽。完全生效区 52 个侧断面中 25 个侵蚀侧、6 个强沉积侧；水深小于 4cm 的宽度最小 5.02cm、最大 72.22cm，局部差异来自断面，不来自贴色散噪点。
- 标准 4.3m 半宽比较：旧浅水带 77.79cm；侵蚀侧 5.59cm；完全沉积侧 92.45cm。此为物理采样，不代表屏幕像素测量。
- 实际210×90m草场：16761个源全部保留，10361个随新岸线/岸宽定位，307丛湿草；15块真实地形网格（.625m格距）贴地待办0，无草根在水域内。尺度/旋转/身份保持。
- 50个花卉地块：3771个源全部保留，1283个随岸形定位，种类/尺度/旋转/身份保持。
- 820个实际水顶点与河床一致；2795个道路采样、全部建筑地基姿态、河网端点/交汇和全部节点水位保持。
- 验证日志：`tools/reports/valley-section-v38-tests.txt`。

仍需实际浏览器检查新的浅滩/切岸是否清晰自然，灰边是否真的被打断，以及走动时307丛湿草接地待办是否归零。旧灰带、远近衔接和整段艺术完成度不因这些单元/离线检查自动结案。默认根位缓存/GI来源绑定由集成方在源码稳定后严格重导出逐值核实，不直接改hash。
