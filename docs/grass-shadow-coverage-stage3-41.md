# 草影亚像素覆盖：第41轮隔离候选

状态：已完成真实 Chrome 编译、同风时域及遮挡叠加验证；未接世界默认，不能据此称草影问题已关闭。

## 根因范围

`tools/audit-grass-shadow41.mjs` 与 `tools/reports/grass-shadow-chain41.json` 核对了默认草颜色/深度使用同一个风函数和共享 uniforms，近阴影光空间固定相机时矩阵稳定。默认 4096 覆盖 110.436m，即每像素 2.696cm，许多细草横截面小于一个阴影像素。真实草面片平移半个/一个像素时出现二值覆盖跳变；PCF 只能过滤已经采到的深度，不能恢复完全漏采的草尖。因此这不是靠另改草风频率能完整解决的问题。

## 候选与正确性

独立入口 `/grass-shadow-coverage41.html`：49个既有草根、每丛完整245面、原风场、真实DEM。地面接收面先以白色写入逐样本深度，原草和树石验证体再以黑色写入；同一 MSAA 样本采用深度遮挡的并集，最后颜色 resolve 保留部分覆盖。4样本600²局部贴图保持默认光空间 texel 尺度，不增加4096/8192级联、不改密度和草面数。它只替换地面直接太阳可见性，其他接收面仍沿用原阴影。

GPU固定4秒读回360000像素，数值0/64/128/191/255分别4334/2175/6067/6767/340657个，证明真正保存了部分覆盖。复制相同草投影者后0通道差异，额外草埋地100m后同为0差异；不存在透明多层累黑或穿过接收面的投影。

## 同条件时域

Chrome 1453×814，原风时刻4至4.7833秒，48个60Hz时刻，两模式相同根、几何、太阳和相机。这里比较单样本接收面mask与4样本mask，不冒充全世界PCF对照结论。

|每帧平方差总和|105.319|27.137|

平方跳变能量下降约74.2%，而总变化量接近，表明保留运动、把整像素闪跳拆成较小覆盖变化。不是把风停住，也不是调淡整个世界。实际浏览器画面已检查，同相位4秒、4.5秒及播放模式草投影随草形移动；细尖仍可能漏采，尚不能宣称观感全部达到目标。

原始采样可通过页面“48帧同风时域对照”按钮或 `grassShadowCoverage41.runTemporal()` 重现，96行保存在页面 `coverageTemporal41.rows`。归档的是工具返回摘要 `tools/reports/grass-shadow-coverage41-browser.json`；图片文件导出未核实，不列为磁盘截图证据。

## 接入前缺口

1. 现候选仅已知地面接收面，草自身、人物、建筑等仍需原深度阴影；不能将这个mask直接当通用shadow map。
2. 世界地表存在16采样器上限。应先确认可复用现有atlas/color attachment或移除同用途旧sampler，不能再盲加一个纹理后称完成。
3. 真实世界需要同源地形、树石和草投影者组成局部窗口，窗口边缘必须与CSM连续交接；不能只画草从而漏掉树石遮挡。
4. 4样本仍是有限覆盖，不是解析覆盖；极细草尖继续有小幅跳变。太阳有限角尺寸、接触关系需单独验证，不应通过加大模糊掩盖。
5. 当前保留原CSM，额外覆盖pass的整体GPU成本还未同条件验收。并行运行时看到的计时不用于采用决定。
6. 全局光照/曝光/色彩专项仍按原顺序，不在此候选改动。

测试：`node --test web/src/v2/grass-shadow-coverage41.test.js`，2/2。生产入口无导入，无默认行为变化。


## 实景接入追加（2026-10-27）

已新增 `grass-shadow-world41.js` 和 `grass-shadow-roots41.js`，接入统一 `renderWorld`（正常帧、首帧、冻结、截图同路径），开关 `grassShadowCoverage41=1`。实际林溪固定构建已 ready、errors为空。仍默认关闭。

**不是叠乘阴影**：仅terrain材料，将CSM原本的 `getShadow(...)` 返回值替换为 `mix(nativeCSM,coverageVisibility,weight)`；CSM级联权重、云影、太阳强度不变。草、树、人物和建筑本身接收原CSM，未关闭其投影。全场景真实可投影mesh共享原几何、实例矩阵、深度风函数、alpha裁剪进入窗口；不生成替代草根/树。光空间窗口按原最近级联texel取整，边缘约12%平滑退回原CSM。

**地形遮挡**：另渲染真实地形首层投影深度。后坡/非首层接收点退回原CSM，避免把前坡的白色接收面错误映射到后坡。该方案局部替代的范围是首层地表，不是通用多接收面透明阴影算法。室内/远处边界仍需跨路线确认。

**真实GPU证据**：林溪terrain程序活跃采样器合计12（含两个新增），当前没有采样器超限。768²、4xMSAA，22.454m窗口，每texel约2.924cm；附加attachment理论下界约24.75MiB（不是驱动显存实测）。GPU mask读回仅0/64/128/191/255，部分覆盖真实存在。实际源caster池616个mesh、549321实例（并非这些全部都提交到GPU）。近草6756根中375根的完整风包围体与光视锥相交；只压紧私有提交矩阵/字段，原完整叶片/index共享。

同页冻结做OFF→ON→OFF，实际HDR目标2660559像素：开启后992029个half-float通道变化，关闭后与最初OFF **0通道差异**；未给场景残留阴影或调色改动。真实scene identity记录在候选pass前后相同。代码针对测试同时覆盖源矩阵/所有近草字段无改动及离返恢复。

**目前不采用的具体原因**：近草视锥裁剪把附加提交从约738.6万三角降至697.3–697.8万，但仍需237–239 draw。大头是全细节近树枝/针叶和其他植被，某近树twig约48.3万、needle约43.6万三角。小mask分辨率只能减少像素工作，不能自动消除这部分重复顶点工作。尚无独占条件GPU性能验收，也不把并行运行时的85ms作为正式性能结果。不能通过删叶片/停树风/关闭树影来采用它。下一步需要复用同源树阴影视锥提交或跨pass顶点处理，再做实景动态/步行窗口边界验收。

因此，草影问题从隔离理论推进到了真实世界可运行、可逐像素恢复的候选；**尚未关闭问题，更不属于第三阶段已完成质量项**。完整光照/色彩专项未提前。
