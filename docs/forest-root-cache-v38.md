# 第38轮：林溪完整根位缓存候选

状态：默认关闭，等待同条件浏览器冷载 A/B；不等于整体加载长尾已解决。

## 保留内容

- 代表林溪 134 个 384m 来源瓦片，137,216 个槽位，80,927 棵树。
- ID 和空槽保持，x/y/z/s/rot/variant 使用 Float64 存储；无量化、减树、密度或 LOD 距离变化。
- 全记录 JSON SHA-256 与提取算法前的实源报告一致：`93ad9d92426f6b8f6e3f3ab26b6642f7cb9a734d296c0bb27af567ed68dea3fd`。
- 原始包 3,903,808 B，gzip 3,101,781 B；单次传输整包，内部按瓦片有独立索引和校验。

## 加载与失效

`forestRootCache=1` 启用，`=0` 或省略沿用原路径。只覆盖默认 v15 空间模型；显式 DEM/河岸/溪流形态实验或 v14 会 bypass。范围外格子仍完整即时生成。

与林木资产并发预取，**不等待缓存即可继续加载**。未就绪时原算法照常，迟到后只影响后续读取，原值一致。原生 fetch 保持 Window 接收者；HTTP gzip 压缩体和透明解压体分别校验对应尺寸及 SHA-256，随后仍逐瓦片验证。缺失、损坏、源指纹变化、实际世界输入变化自动回退，原因保留在 `ecology.stats.forestRootCache`。取消或释放后不激活缓存。

算法提取至 `forest-root-source.js`，ecology 的岸草修改不影响签名。Vite 虚拟模块来自当前实际源文件 SHA-256；实际已解码 DEM、地被字节和对象/元数据分别由 WebCrypto 校验。关闭候选时没有大数组扫描或缓存网络请求。任何空间源变更需要重新生成。

## 验证

- 生成脚本逐一对比 137,216 槽位的原过程输出和二进制还原值，包括空槽、负坐标和对象字段顺序。
- 新增 9 项针对检查通过：当前源绑定、开关/空间实验旁路、全记录一致、输入变更失效、缺失/损坏回退、瓦片身份/占用检查、取消/释放、浏览器 fetch 接收者、HTTP 透明解压后完整原始校验。
- 已有布局、排除和 world-data 24 项通过。
- 已移除可选缓存的 load 尾部强制 await；这一收尾仅取消等待，不改变根记录和校验。
- Node 生成时间不作为浏览器或整体冷启动提升证据；3.1 MB 的额外传输、哈希及解码要纳入同条件冷载评估。

生成命令：`node tools/build-forest-root-cache-v38.mjs`。
浏览器：相同林溪 URL 分别加 `forestRootCache=1` / `forestRootCache=0`。若同时带 `brookLandform` 等空间形态查询，本轮候选会按约定 bypass，不能作为有效缓存开关对照。

仅免去代表范围的重复根位 CPU 计算；并未减少 GPU 提交、三角形、阴影采样或其他资产加载。默认关闭等待实际浏览器验收，尚不推广全世界或宣称整体帧率/冷启动完成。
