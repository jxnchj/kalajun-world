# 步道终点木屋木作：来源诊断、实现与验收

来源诊断后已完成目标木屋屋顶与梁的材质派生和浏览器检查；未改变世界整体色彩。最终状态见文末实际验收记录。

## 已核实的原因

原 `cabin_small.glb` 内嵌 `wood_log`、`wood_plank` 与 `assets/tex/` 中对应512² PNG逐字节SHA相同，已查看两张实际图片。不是推测当前模型仍使用旧生成器：当前打包资产确实保留了这些图。

- `wood_plank` SHA：`829d1b9024fb95d974bb575ea03a47dccba0a0d9b23182221ac6bc11d2d9a817`。图像把4条板缝、每板9道正弦木纹及钉点一起画进颜色，长纹自身已经规则、模糊。
- `wood_log` SHA：`7dc37105021ef335f8e90fbebe7f9f1b2393ef2c2a575e922d7188d8bfa7375f`。图像包含规则蛇纹、4个重复树节，以及模拟圆木亮带的颜色调制。该亮带与真实太阳方向无关。
- `cabin.py` 的两坡屋面各是一块9.8m宽的大盒板，`uv_scale=.5`；横向每2m重复整图，约4.9次。纹理一张里又有4条“板”，所以大面重复与细横条同时出现，真实几何没有逐块板条。
- 3根檩/脊梁长9.6m，`lib.log` 的 `u=长度/2`、`v=圆周比例`，每根从同一相位开始，约重复4.8次。`seed`只扰动几何半径/相位，不改变UV原点，所以多梁木结和波纹容易完全对齐。

## 可执行的局部改善

优先做这一个精确实体的材质/UV派生，不重生整座木屋，不扩到另外8栋，也不同时重做所有墙体。

1. 从原GLB索引连通组件提取两坡屋面、3根大梁及必要端面，保存每个组件的几何/UV校验。`plank`混有地板、窗框、门廊，`log`混有墙与柱，不能整材质替换。像玻璃一样隔离选中实体和目标批次。
2. 屋面采用与斜坡板条长轴一致的米制坐标：真实板宽约14–18cm只是设计初值，先与实际屋内机位比较，再定。沿板随机平移扫描区、错开纵向接头，不能靠整面高频噪声隐藏重复。凹缝只做浅normal/roughness，不把宽黑缝画进底色。
3. 梁侧面按原轴向长度和真实圆周长度采样，端面单独映射；每梁给稳定随机偏移，避免同相树节。长轴翻转/选段保留纤维方向，不做任意角度旋转。保留当前圆木不规则轮廓和全部细节。
4. 可复用项目已持有、授权和来源齐全的木材扫描流程，屋面先评估现有 Oak Veneer 01 派生的颜色/normal/roughness；梁应先查看现有rough wood图是否适合去皮圆木，再决定，不因现成就强行套用抛光家具纹理。只需局部两套共享PBR纹理及组件坐标，不需要Aholo或重做大GLB。
5. 按现有原木/板材平均线性反照率校准新底色，去掉原图固定亮带，让粗糙度和法线承担高光变化。只保持低频颜色输入，不声称因此得到完整室内GI。若以后真的改变木作几何，则另行真实重烘相应AO/GI。
6. 小样先看同机位屋顶、梁端、沿墙移动：验证纹理方向、物理尺度、无同相重复、无遮挡与接缝、不闪烁，并记录纹理字节/材质批次成本。接受后才推广同木作体系，不在这里提前开展全局光照与色彩专项。

中间态边界：原屋内仍使用已有低阶间接光近似；这里只解决木作资产的纹理来源、方向、尺度与重复。窗透视修复不会自动消除这些木纹缺陷，也无需等待阶段5才可准备这一局部资产改善。
